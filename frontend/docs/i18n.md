# Internationalization (i18n)

Kontrol uses **vue-i18n v11** in Composition API mode (`legacy: false`).

---

## File locations

```
frontend/src/locales/
  index.js   ← i18n setup (register languages here)
  en.json    ← English translations
  es.json    ← Spanish translations
```

---

## Key naming convention

Keys follow a `module.section.key` structure, always in camelCase:

```
auth.login.title
dashboard.kpi.totalProjects
reports.detail.sideActionGenerate
```

Both locale files must always have the same keys. If a key is missing in the active locale, vue-i18n falls back to `en` automatically (`fallbackLocale: 'en'`).

---

## Using translations

### In templates

`$t()` is globally available — no import needed:

```html
<h1>{{ $t('dashboard.title') }}</h1>
<button>{{ $t('reports.header.createReport') }}</button>
```

### In `<script setup>`

Import `useI18n` and destructure `t`:

```js
import { useI18n } from 'vue-i18n'
const { t } = useI18n()

const label = t('reports.kpi.activeProjects')
```

### With interpolation

```json
"activeRate": "{rate}% active"
```

```html
{{ $t('admin.dashboard.kpi.activeRate', { rate: activeRate }) }}
```

### With pluralization

Use `count` as the variable name — it drives the plural form selection:

```json
"members": "{count} member | {count} members"
```

```html
{{ $t('teams.list.members', { count: total }) }}
```

### Static arrays with translated labels

Arrays that contain translated strings must be `computed()` so they react to locale changes. A plain `const` array is evaluated once at setup time and won't update when the language switches.

```js
// correct
const filters = computed(() => [
  { key: 'all',    label: t('reports.view.filters.all') },
  { key: 'active', label: t('reports.view.filters.active') },
])

// won't update on language change
const filters = [
  { key: 'all',    label: t('reports.view.filters.all') },
]
```

## Adding a new key

1. Add the key to `en.json`
2. Add the same key with the Spanish translation to `es.json`
3. Use `$t('your.new.key')` in the component

Both files must stay in sync. A key present in one but missing in the other will silently fall back to English.

---

## Adding a new language

1. Create `frontend/src/locales/fr.json` mirroring the structure of `en.json`
2. Register it in `frontend/src/locales/index.js`:

```js
import fr from './fr.json'

export const i18n = createI18n({
  messages: { en, es, fr },
})
```

3. Add the option to the language switcher in `AppNavbar.vue` and `AdminNavbar.vue`:

```html
<button class="lang-opt" :class="{ selected: locale === 'fr' }" @click="setLocale('fr')">Français</button>
```
