2. Nuestra elección: Vitest (front + back)

Integración con nuestro stack

  • Frontend ya usa Vite → los tests reutilizan vite.config.js (alias @/, plugin Vue) sin duplicar nada.
  • Backend ESM puro → Vitest lo soporta nativamente; Jest requiere flags experimentales.
  • Recomendado oficialmente por el equipo de Vue.

Rendimiento

  • Transformación con esbuild + workers en paralelo.
  • Watch mode tipo HMR: re-ejecuta solo los tests afectados.

Comunidad y documentación

  • +10M descargas/semana; default en Vue, Nuxt, Astro, SvelteKit.
  • Docs completas (vitest.dev), releases frecuentes.
  • API compatible con Jest → curva de aprendizaje ≈ 0.

Robustez ("baterías incluidas")

  • Mocks, spies y fake timers integrados (vi.*).
  • Cobertura v8 integrada.
  • Un solo framework para todo el monorepo → CI simple.

Complementos: @vue/test-utils happy-dom @vitest/coverage-v8

import { defineConfig } from 'vitest/config'

export default defineConfig({
  test: {
    environment: 'node',
    globals: true,
    include: ['tests/**/*.test.js']
  }
})

frontend/vitest.config.js

import { defineConfig, mergeConfig } from 'vitest/config'
import viteConfig from './vite.config.js'

export default mergeConfig(
  viteConfig,  // hereda alias @/ y plugin Vue
  defineConfig({
    test: {
      environment: 'happy-dom',
      globals: true,
      include: ['tests/**/*.test.js']
    }
  })
)

Scripts en ambos package.json: npm test · npm run test:watch · npm run test:coverage

4. Ejemplo backend #1 — Middleware JWT (requireAuth)

it('acepta un token válido, adjunta el payload en req.user y llama next()', () => {
  const payload = { id_usuario: 7, email: 'ana@kontrol.gt', nombre_rol: 'admin' }
  const token = jwt.sign(payload, SECRET)
  const req = { headers: { authorization: `Bearer ${token}` } }
  const res = buildRes()   // { status: vi.fn(), json: vi.fn() }
  const next = vi.fn()

  requireAuth(req, res, next)

  expect(next).toHaveBeenCalledOnce()
  expect(req.user).toMatchObject(payload)
})

it('responde 401 cuando el token está expirado', () => {
  const token = jwt.sign({ id_usuario: 7 }, SECRET, { expiresIn: '-1s' })
  /* ... */
  expect(res.status).toHaveBeenCalledWith(401)
})

5 escenarios: token válido · sin header · esquema no-Bearer · expirado · secreto incorrecto. Sin servidor ni base de datos: req/res simulados con vi.fn().

4. Ejemplo frontend #1 — Store Pinia con fetch mockeado

it('loadEmpresas consume la API y auto-selecciona la primera empresa', async () => {
  const empresas = [{ id_empresa: 5, nombre: 'Gamma' }]
  vi.stubGlobal('fetch', vi.fn().mockResolvedValue({
    ok: true,
    json: async () => ({ data: empresas }),
  }))

  const store = useAuthStore()
  store.setToken('jwt-de-prueba')
  await store.loadEmpresas()

  expect(fetch).toHaveBeenCalledWith('/api/companies/my-companies',
    { headers: { Authorization: 'Bearer jwt-de-prueba' } })
  expect(store.idEmpresaActual).toBe(5)
})

7 tests del store: login/logout, persistencia en localStorage (real, provisto por happy-dom), getters de permisos y selección de empresa. La API se aísla con vi.stubGlobal.

6. Conclusiones

  • Configuración casi nula: 8 líneas de config en backend; el frontend hereda vite.config.js completo (alias, plugin Vue) con mergeConfig.
  • Velocidad que cambia el flujo de trabajo: suites completas en <1 s y watch mode instantáneo hacen viable correr los tests en cada guardado, no solo en CI.
  • Mocking integrado suficiente: vi.fn() (req/res de Express), vi.stubGlobal (fetch) y vi.useFakeTimers (fechas) cubrieron todos nuestros casos sin librerías extra.
  • Los tests encontraron y ayudaron a corregir un bug real el primer día: el evento click duplicado en Button.vue por no declarar emits; el test quedó como prueba de regresión.
  • Un solo framework para el monorepo reduce carga cognitiva: mismos comandos y API en backend y frontend.
  • Contras honestos: comunidad más joven que Jest y menor ecosistema de plugins; la ventaja se reduce en proyectos sin Vite.

Veredicto: Vitest es la elección correcta para Kontrol — en ~2 horas obtuvimos 53 pruebas listas para CI que protegen autenticación, autorización, validación y lógica de negocio.
